# Contributing to FOX

Thank you for your interest in FOX. The project is currently in its design stage, so contributions that clarify requirements, test assumptions and improve the architecture are especially valuable.

## Ways to contribute

- Discuss language design proposals.
- Review syntax and type-system decisions.
- Improve documentation.
- Prototype compiler components.
- Add tests and benchmark methodology.
- Research optimization and verification techniques.
- Report ambiguities and inconsistencies.

## Before making a change

1. Read the [README](README.md).
2. Check the [Specification](SPECIFICATION.md).
3. Check the [Roadmap](ROADMAP.md).
4. Search existing issues and pull requests to avoid duplicate work.

## Design proposals

For substantial language or compiler changes, open an issue or proposal that explains:

- The problem being addressed.
- The proposed design.
- Alternatives considered.
- Safety and correctness implications.
- Performance implications and how they could be measured.
- Compatibility impact.
- Open questions.

Avoid presenting unmeasured performance expectations as facts.

## Pull requests

- Keep changes focused.
- Include tests for implementation changes.
- Update documentation when behavior or design changes.
- Explain trade-offs in the pull request description.
- Do not silently change established semantics.

## Current project status

The language and implementation are not stable. Early contributors should expect design changes while the specification is being developed.

A code of conduct and license will be added when the project maintainers select and publish them.
